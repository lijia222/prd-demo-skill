# `demo` 模块：生成与交付工作流

## 意图分流

- 新建、废弃重建、按计划重生：Apply。
- 修改已有 Demo 的局部结构、交互或字段：优先 `change-sync`。
- 只补 `data-*` 功能标记：进入 marker 子流程。
- 修改意见、可讨论方案：Opinion，不写文件。

## 步骤 0：页面地图

动手前按 PRD 把页面分为：真改动页（必须做）、沿用页（闭环需要时分批做）、不进 Demo 的说明页（不做）。严格遵守用户已冻结的 Demo 最小集，不擅自扩页。

页面地图至少记录：

| 页面 | 端 | 现网源 | 规模 | 真改动点/PRD 锚点 | 非改动区策略 |
|---|---|---|---:|---|---|
| `<PAGE>` | `<WEB/MOBILE>` | `<PATH/无现网页>` | `<SIZE>` | `<DELTA>` | `<RULE>` |

找不到现网源时必须询问：走 G 通用生成，还是做近似壳；不得默默用模板冒充还原。

## 步骤 1：生成模式 R/G/E

| 模式 | 适用 | 规则 |
|---|---|---|
| R | 有现网或要求 1:1 | 只读还原基线，再叠真实差量和标记 |
| G | 无现网且用户不要还原 | 通用模板生成，头部注明无现网页 |
| E | D3 准入且用户确认 | 产品资产目录内工程化实现，交付静态 build |

R 是有基线时的默认模式。只读合法，可写业务代码仓或将其 fork 为 Demo 基底不合法。非改动区字段、筛选、按钮和布局尽量与基线一致；只叠新字段、枚举、显隐、门禁和异常路径。

## 步骤 2：D1/D2/D3 形态

- D1：不超过 3 个视图、约 800 行以内、无图表、单模块、非迭代版本。
- D2：视图超过 3 个、超过约 800 行、有图表、多模块或需要功能标记，任一满足即用 D2。
- D3：至少两项准入信号（多次演进、D2 难维护/超大文件、重路由重状态、已承诺静态部署）并获用户确认；不默认使用。

多页或跨端 R 模式必须先锁定还原计划：基底、还原深度、标记方式、交互边界、交付批次、组件深度和外壳深度。

## 步骤 3：技术与生成

后台表格/表单按项目规范锁定框架和 CDN 版本；移动端按现网结构还原；图表依赖锁定版本并提供离线降级。对接配置和密钥默认不进 Demo UI。业务 mock 只为演示服务，不代替真实接口契约。

## 步骤 4：交付门禁

头部注释应包含 Status、版本、形态、模式、PRD、现网参考/差异和一致性检查状态。页面在 `</body>` 前接入 PRD 查阅入口，`data-prd` 相对路径必须有效。使用 HTTP 服务验收，不用 `file://`。

新建、重建、规则/交互/字段变更完成后执行 Full 一致性审计；纯错别字或无规则展示可 scoped。R 模式还需确认真改动可演示、非改动区对齐、feature-id 唯一、跨端 README 闭环。
