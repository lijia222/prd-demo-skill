# `consistency-audit` 模块：17+2 项审计

## 模式

- **Full**：L2/L3、Frozen 前、用户要求全面审计；检查 17 项，存在开发补充时增加 #18/#19。
- **Scoped-display**：L1 展示差量、纯样式或文案强化；检查相关展示边界。
- **Scoped-devnote**：只写开发补充；检查补充是否越权和入口是否有效。

输入至少需要 PRD 和 Demo；数据字典、开发补充和多文档入口按存在情况加入。缺少必要路径时询问，不猜文件。

## 静态一致性（1-6）

1. 字段双向覆盖：PRD 字段 ↔ Demo mock/表单/表格。
2. 字段类型一致：String/Number/Boolean/Date 与 mock 值一致。
3. 状态枚举覆盖：PRD 与标签、颜色、筛选、映射互相覆盖。
4. 交互按钮覆盖：PRD 操作清单与 Demo 入口一致。
5. 布局对齐：PRD 布局描述与主要 DOM 区域、列顺序一致。
6. 接入规范：PRD 查阅脚本存在，`data-prd` 路径有效，多 PRD 配置完整。

## 业务逻辑（7-12）

7. 流程闭环：每个状态有进入和离开路径，终态例外。
8. 角色权限闭环：PRD 中角色在 Demo 有入口或可见性表现。
9. 异常路径覆盖：空态、校验失败、超时、权限不足或网络失败至少有对应反馈。
10. 业务规则一致：公式、阈值、金额、比例和时长在背景、详设、验收一致。
11. 跨模块闭环：上游输出能被下游输入消费，字段类型匹配。
12. 金额/数量/时间口径：单位、精度、时区和格式一致。

## 技术可行性（13-17）

13. 数据来源明确：自建字段、外部 API、计算字段或用户输入可追溯。
14. 接口契约清晰：调用时机、入参、出参和失败处理明确，mock 不丢关键字段。
15. 性能可行：大列表分页、大批量异步、图表采样等方案合理。
16. 状态持久化：多步骤表单/向导刷新和退出行为符合 PRD。
17. 权限粒度可落地：菜单、操作、字段、行级设计有实现路径。

## 开发补充差量（18-19）

18. 补充未越权：正式新字段、公式或状态必须回写 PRD；补充只表达差量和落地细节。
19. PRD 轻入口有效：对应章节有存在的相对路径链接和一句话说明。

## 输出和评级

只需列问题项，但每项要给文件/章节定位、具体建议和红/黄级别。任一红项阻塞 Frozen；黄项由用户决定；未创建开发补充不是红项。报告末尾给出下一步建议，并注明 Full 或 Scoped 范围。
