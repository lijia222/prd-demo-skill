# `change-sync` 模块：已有制品变更同步

## 意图

- Opinion：讨论修改意见、是否合并、是否删除；只给方案，不写文件。
- Apply：用户明确要求落盘，执行完整同步流。
- Dev-note：只整理开发补充；规则缺口提示回写 PRD。

Opinion 转 Apply 后必须从头确认落点，不得把讨论内容偷偷写入文件。

## Apply 前门

1. 确认目标 PRD、Demo、数据字典、CHANGELOG 和项目说明。
2. 确认是否已进入开发（`in-dev`）；未知必须询问，不能猜。
3. 确认变更等级和是否需要用户确认开发补充。
4. Review/Frozen 制品必须规划精确 diff；禁止整文件重写。

## 变更等级

| 级别 | 典型改动 | 最低要求 |
|---|---|---|
| L1 | 错别字、无语义文案、纯样式 | 局部修改；行为变化才询问补充 |
| L1 展示差量 | 已有规则的展示强化 | Demo 变更、可 scoped 审计 |
| L2 | 单字段、交互、视图、枚举、验收 | 反向影响、矩阵、diff、CHANGELOG、审计 |
| L3 | 多模块、状态机、接口、权限、数据模型 | 全量影响、数据字典、所有 Demo、审计 |
| L0/P0 | 主框架或紧急修复 | 独立拆分/补登记录，不得用 P0 逃避评审 |

## 反向影响

- PRD 改字段 → Demo mock、表单、表格列。
- PRD 改枚举 → Demo 标签、颜色、筛选和状态机。
- PRD 改流程 → Demo 按钮、跳转、可见性和异常反馈。
- Demo 改展示 → PRD 字段字典、验收或轻入口。
- Demo 改交互 → PRD 操作描述和异常路径。
- data_dict 改动 → 全文检索所有引用。
- 套件变更 → 版本指针、权威地图、兄弟文档链接、共享术语。

## 开发补充和记录

只有用户确认后才写开发补充。内容用通俗语言说明“改哪里、改成什么、怎么测、边界是什么”，不是第二份 PRD。写完立即在 PRD 对应章节增加轻入口；L2/L3 和已写补充的变更必须登记 CHANGELOG。

纯结构整理若业务结论不变，默认不写补充；错别字也不因未写补充而判红。

## 完成后

输出变更影响矩阵、文件 diff、同步结果和未验证项。存在 Demo 或规则/交互变化时运行 `consistency-audit`；只改开发补充时至少检查 #18/#19。
